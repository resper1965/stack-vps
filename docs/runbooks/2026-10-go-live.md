> **Regras de execução:** um comando por vez, cada um com aprovação do dono; nenhum valor de segredo passa pela conversa, por argv ou por log
> (o `43` pede cada valor com entrada oculta, num terminal do dono). Acesso à VPS: `ssh stack` (usuário `dev`, sudo sem senha). O `LocalForward 4096`
> do ssh config pode avisar `bind: Permission denied`: é inofensivo.

**Critério de pronto:** `stack-doctor` sem nenhum `FALTA` (`pend` só com dono nomeado). Cada fase só termina quando as linhas da sua seção estão `ok`.

```sh
stack-doctor            # como dev; sem sudo -n o que exige root/agente vira "pend"
stack-doctor | sed -n '/^9router$/,/^$/p'     # só uma seção (troque o nome)
```

Como ler a saída: `ok` = conferido; `pend` = depende do dono ou de permissão que o doctor não tem; `FALTA` = errado ou ausente, trate antes de
seguir. Seções: código, acesso, permissões, opencode, 9router, modelos, clis, ci, restos. Exit 1 se houver `FALTA`. Nunca imprime segredo.

Atalho para os usuários: `AG='sudo -u agente -H bash -c'` (o `cd ~` evita cwd ilegível para o `agente`).
