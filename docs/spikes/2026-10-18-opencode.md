# Spike OpenCode (2026-10-18)

Só documentação e código público (nada instalado ou executado). Fontes: https://opencode.ai/docs/web/, https://opencode.ai/docs/plugins/, https://opencode.ai/docs/sdk/, script de instalação v1 (`https://opencode.ai/install` redireciona para `anomalyco/opencode`, branch `v1`) e `packages/sdk/js/src/gen/types.gen.ts` (branch `v1`). Última versão 1.x no npm (`opencode-ai`): 1.19.3 em 2026-10-18. Existe também uma linha 2.x; o instalador v1 recusa versões 2.x, e a doc avisa que as duas podem conflitar. **Fixar 1.x.**

| Pergunta | Resposta | Evidência |
|---|---|---|
| Flags da web em `127.0.0.1:4096` | `opencode web --hostname 127.0.0.1 --port 4096`. Sem `--port` ele escolhe uma porta livre (por isso a porta precisa ser explícita). O padrão de `--hostname` já é `127.0.0.1`; passar explícito não faz mal. | https://opencode.ai/docs/web/ |
| Variável da senha | `OPENCODE_SERVER_PASSWORD`. Usuário padrão `opencode`, trocável por `OPENCODE_SERVER_USERNAME`. A doc avisa que sem a senha o servidor fica sem proteção (aceitável só local). Para o serviço: arquivo de ambiente 0600, nunca na unidade. | mesma página |
| Como fixar a versão na instalação | Script oficial v1: `curl -fsSL https://opencode.ai/install \| bash -s -- --version 1.19.3` ou `VERSION=1.19.3 bash`. Instala em `$HOME/.opencode/bin/opencode`; `--no-modify-path` evita mexer no rc do shell. Alternativa: `npm install -g opencode-ai@1.19.3`. Na página de instalação a doc não descreve fixação; isto vem do próprio script. | script v1 em `anomalyco/opencode` (`refs/heads/v1/install`: `-v\|--version`, `requested_version=${VERSION:-}`, rejeita 2.x) |
| Pasta de plugins | **`~/.config/opencode/plugins/`** (global) e `.opencode/plugins/` (projeto), **no plural**. O plano escreve `plugin/` (singular): corrigir nas Tasks 9 e 15. Arquivos são carregados no início, então é preciso reiniciar o `opencode-web` após instalar. | https://opencode.ai/docs/plugins/ |
| Formato do módulo | Módulo JS/TS que exporta uma ou mais funções de plugin: `export const MeuPlugin = async ({ project, client, $, directory, worktree }) => ({ event: async ({ event }) => { ... } })`. `$` é o shell do Bun; `client` é o SDK do OpenCode. Tipagem opcional com `Plugin` de `@opencode-ai/plugin`. | mesma página |
| Evento de sessão ociosa | **`session.idle`**, tratado no gancho `event` com `event.type === "session.idle"`. Outros: `session.created`, `session.updated`, `session.status`, `session.error`, `session.deleted`, `session.compacted`, `session.diff`. | mesma página |
| Campos do evento | **Só `sessionID`**: `{ type: "session.idle", properties: { sessionID: string } }`. Título e diretório **não vêm no evento**; vêm do objeto `Session` (`id`, `projectID`, `directory`, `parentID?`, `title`, `version`, `time`, ...), obtido via `client.session.get` ou do último `session.updated` (`properties.info: Session`). O plugin deve guardar o `info` de cada `session.updated` num mapa por `id` e consultá-lo no `session.idle`. O nome exato do método do `client` para buscar uma sessão **não foi confirmado**: conferir no `types.gen.ts`/SDK da versão fixada antes da Task 15. | `types.gen.ts` (`EventSessionIdle`, `EventSessionUpdated`, `Session`) |
| Ociosidade dispara várias vezes? | Não documentado. Tratar `session.idle` como possivelmente repetido por sessão e deduplicar por `sessionID` com janela de tempo na Task 15. | lacuna da doc; confirmar na VPS |

## Decisão

Valores para as Tasks 9 e 15 (PROVISÓRIOS só no que depende de rodar):

- Unidade `opencode-web`: `ExecStart=/home/agente/.opencode/bin/opencode web --hostname 127.0.0.1 --port 4096`, `EnvironmentFile=` 0600 com `OPENCODE_SERVER_PASSWORD` (e opcionalmente `OPENCODE_SERVER_USERNAME`).
- ATENÇÃO: o plano cita "OpenCode 2.x" (linha 16). Esta pesquisa cobre a linha 1.x (a que `opencode.ai/install` instala hoje); a 2.x tem script próprio (`/v2/install`) e não foi pesquisada. Conferir na VPS qual linha roda antes das Tasks 9 e 15.
- Versão: instalar com `--version <1.x fixa>` (hoje 1.19.3; confirmar na VPS qual está instalada com `opencode --version` e usar a mesma, para não trocar de versão junto com o redesenho). Nunca 2.x.
- Plugin de aviso (Task 15): arquivo `~/.config/opencode/plugins/<nome>.js` do usuário `agente`; guardar `info` dos `session.updated`; no `session.idle` montar o aviso com `title` e `directory` do mapa, deduplicando por `sessionID`.
- Pendências que exigem a VPS: confirmar a versão instalada, que `plugins/` plural é lida por essa versão, a chamada do `client` para buscar sessão, e a frequência do `session.idle`.
