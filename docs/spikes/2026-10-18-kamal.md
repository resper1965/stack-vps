## Modelo de `config/deploy.yml` para o template `sistema` (a validar na etapa 6)

```yaml
service: sistema
image: ghcr.io/<org>/sistema
servers:
  web:
    - <ip-do-servidor>
registry:
  server: ghcr.io
  username: <usuario>
  password:
    - KAMAL_REGISTRY_PASSWORD
proxy:
  ssl: true            # com DNS publico; sem DNS: bloco certificate_pem/private_key_pem, ou ssl: false atras do proxy do cliente
  host: sistema.<dominio>
  healthcheck:
    path: /up
env:
  secret:
    - DATABASE_URL
accessories:
  postgres:
    image: postgres:16
    host: <ip-do-servidor>
    port: "127.0.0.1:5432:5432"
    env:
      secret:
        - POSTGRES_PASSWORD
    directories:
      - postgres-data:/var/lib/postgresql/data
```

Os segredos ficam em `.kamal/secrets` lido de fora do repositório (nunca versionado). Com a imagem Docker do Kamal, os adaptadores de segredo não existem: exportar as variáveis no ambiente e passá-las com `-e`.

## Decisão

Comando-padrão de deploy (a partir de um Linux com Docker e agente SSH): o alias acima fixado numa tag (`2.12.0`, depois de confirmar que existe) e `kamal deploy` (primeira vez: `kamal setup`, que também sobe os acessórios). Rollback de app: `kamal app containers -q` e `kamal rollback <versão>`. Rollback de banco é por backup, não pelo Kamal. A escolha do modo TLS por cliente (Let's Encrypt, certificado próprio ou `ssl: false`) vai como pergunta do `/novo-projeto`. Pendência para fechar: confirmar a tag fixada e testar `kamal setup` num servidor descartável (exige VPS).
