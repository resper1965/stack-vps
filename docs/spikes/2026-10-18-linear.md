# Spike Linear (2026-10-18)

Só documentação e schema público (nenhuma chamada, nenhuma chave). Fontes: https://linear.app/developers/graphql, https://linear.app/developers/rate-limiting, https://linear.app/docs/project-status, https://linear.app/pricing e o schema `packages/sdk/src/schema.graphql` de https://github.com/linear/linear (branch `master`, baixado em 2026-10-18). Tudo que depende do workspace real (status existentes, chave do time, plano) é **não verificado, exige credencial**.

## Diferenças em relação ao plano

- Nenhum nome de campo do plano estava errado (`projectStatuses`, `teams(filter:{key:{eq}})`, `projectCreate(input:{name,teamIds,statusId})`, `projectUpdate(id,input:{statusId})`).
- O enum de tipo tem um sexto valor, `planned`, ausente de `TIPO_DO_ESTAGIO`; o mapa continua válido, só não o usa.
- O plano pede o `id` do time com `teams(...) { nodes { id } }`; vale acrescentar `key` para conferir que o filtro devolveu o time certo.
- Cabeçalho: chave pessoal sem `Bearer` (o plano deixava "conforme o spike").
- Idempotência: `ProjectCreateInput.id` aceita UUID gerado pelo cliente. Gravar o UUID no vínculo antes de chamar a API evitaria duplicar projeto se a resposta se perder.

## Verificação pendente (exige a chave de resper@bekaa.eu, só leitura)

Uma consulta: `{ projectStatuses(first: 50) { nodes { id name type } } teams(first: 50) { nodes { id key name } } }`, com a chave num cabeçalho `Authorization` sem eco no terminal ou log. Conferir os nomes dos status, a chave do time e o plano em Settings > Billing.

## Decisão

**PROVISÓRIA.** Usar o **mapeamento padrão por tipo** (`TIPO_DO_ESTAGIO`, já no plano) enquanto não se conhecem os status reais; criar status personalizados com os nomes dos estágios (para a regra "nome igual ao estágio" de `escolher_status` valer) só com aprovação do Ricardo, à mão em Settings > Project statuses, em nível de workspace (disponível em todos os planos). `LINEAR_TEAM_KEY`: a definir a partir da consulta pendente; sem ela a Task 19 não deve habilitar o timer. Autenticação: `Authorization: <chave>` sem prefixo.
